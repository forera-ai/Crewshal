# ADR 0005: Official Codex subscription interface for the Phase 2D pilot

Status: accepted for implementation and preparation by the owner on 2026-10-09. The owner answered “Approve official subscription route” to the explicit question linked to [the proposal](../PHASE-2D-SUBSCRIPTION-ROUTE-DECISION-2026-10-09.md). The proposal's pending status is dated history; its bytes and source evidence remain unchanged.

Replace the API-key-only proxy path for the single bounded Codex pilot with the official app-server stdio interface. Codex owns its existing model/tool loop. The coordinator may implement only a finite, source-bound initialization, account observation, one thread and one turn, followed by actual terminal capture. Use the selected subscription model; no API key, metered fallback, purchased credits, reset consumption, Jev call, custom gateway or custom model loop is authorized.

Use an exclusively owned private authentication home prepared through official managed device login. Native authentication and its transport authority must remain inaccessible to code tools, descendants and the credential-free validator. Restricted tool read roots and the official sandboxed filesystem helpers are a source-supported candidate; readonly authentication files or a legacy full-read workspace policy do not establish separation. Qualify every enabled tool and all credential, alias, process-memory, inherited-FD and replay refusals before adoption.

All original ceilings, the five-second origin before worker creation, one-second recovery grace, stopped-native admission, independent watchdog/parent/wrapper readback, and fixed final 30-second reserve in the 600-second batch remain mandatory. Account events, turn completion and process exits do not supply physical release or reuse authority. [ADR 0004](0004-retained-terminal-storage.md) governs retained storage and full capacity charges.

The owner subsequently answered “Approve only vendor authentication recovery” to the exact narrow amendment in [the subscription auth boundary](../PHASE-2D-SUBSCRIPTION-AUTH-BOUNDARY-2026-10-09.md). Permit stock managed authentication refresh and HTTP 401 recovery inside the unchanged attempt: force HTTP, disable unbounded connection retries, and keep ordinary request/stream retries zero. Managed recovery permits at most two additional Responses submissions per logical request, not per turn; proactive refresh has no global per-turn count cap in the inspected path. This is not a hard quota cap. No second turn, coordinator/task/storage retry, model fallback, deadline extension or metered API is authorized. External token extraction or an unsupported authentication mode is not a workaround. Both approvals cover implementation/preparation only and establish no runtime capability.

Installation, login, native/provider/model execution and non-hard subscription quota exposure require a concrete separately approved batch. Effective installed identities, credential separation, original limits, retained ownership/accounting, fresh exact qualification and actual candidate/validator acceptance remain outstanding. Publication and release retain their existing gates. No Phase 2E is authorized.
