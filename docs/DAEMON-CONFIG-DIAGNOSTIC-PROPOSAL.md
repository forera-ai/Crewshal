# Bounded daemon configuration diagnostic proposal

Status: proposed; not executed. Phase 2C only.

The complete operational freeze gate in [the continuation prompt](PHASE-2C-RESUME-PROMPT.md) requires daemon configuration and download behavior before operational creation. The pinned CLI says settings reads start the daemon. Current Docker model documentation describes automatic model-service startup/runtime download even without model selection. Static strings are not sufficient evidence of effective behavior. The exact participating SBX bytes are verified, but the downloaded model runtime and effective settings remain unresolved. An operational guest cannot start under these conditions.

Request a narrowly scoped owner exception for [this exact diagnostic profile](qualification/phase-2c-daemon-config-diagnostic-v1.json). It starts only the pinned trusted daemon and reads settings, in an existing systemd service under UID/GID 65534, no capabilities, no-new-privileges, private network/devices/tmp, protected host files/home and empty synthetic state. Limits: 256 MiB, one CPU, 128 tasks, zero swap, ten seconds, 64 MiB temporary filesystem, 65,536 bytes per output stream and thirty seconds total including independent cleanup. These are within the approved aggregate envelope; original worker limits remain unchanged.

The trusted observer checks effective service/kernel placement and final owned process/unit/KVM cleanup. No external networking or dynamic download is permitted. No template/image load, VM, worker/native/validator, credential-store/login, provider request, host package change or deletion is authorized. The shell body and binary hashes are recorded in the profile. [Exact diagnostic source](qualification/phase-2c-daemon-config-diagnostic-v1-runner.txt) binds host executables and ldd-reported dynamic libraries through the [toolchain inventory](qualification/phase-2c-current-host-toolchain-v1.json); absent/drifting identity refuses. This inventory is not a complete OS filesystem or Python standard-library attestation. A failure to start in these restrictions is an unavailable diagnostic, not permission to relax controls.

This is not a full operational identity freeze, inner qualification or a resource-envelope change. The droplet remains needed and must be retained after this diagnostic, including if startup fails. Earlier diagnostics and failures remain separate.
