Date: 2026-10-16. Status: proposed; freeze blocked.

The package contains no evaluation runner or new runtime interface.
The index detects changed preparation bytes; it does not authenticate approval or grant execution authority.
Null fields record missing evidence. They do not mean zero, an empty grant, or an implicit default.

## Corpus access and legal provenance

The candidate list preserves three repositories per stack: two development repositories and one proposed hold-out.
Python, TypeScript, Swift, and .NET each retain a real repository slot.
The public GitHub commit API resolved each tag to a full revision.
Unauthenticated HTTPS retrieval supplied each root license digest and byte count.
Pinned license links identify the evidence. No upstream implementation or license text enters this package.

The root notices permit candidate screening subject to their recorded terms.
They do not establish every file's license, dependency obligations, source suitability, or permission for a specific export.
For example, [Click's notice](https://github.com/pallets/click/blob/934813e4d421071a1b3db3973c02fe2721359a6e/LICENSE.txt) requires notice preservation.
[Dapper's notice](https://github.com/DapperLib/Dapper/blob/bd4f75b512de3e00f2c2631d5309961a1ecfea23/License.txt) gives its logo separate conditions.
An independent engineer must verify file licenses, bundled data, dependencies, and notices before corpus freeze.
Preserve required notices in later source copies and permitted exports.

The development inspection read root manifests and public tree metadata only.
The recorded workflow paths do not establish their commands, service requirements, or successful execution.
Observed toolchain ranges and SDK roll-forward declarations do not pin an execution environment.
Exact binaries, dependencies, locks, images, checks, services, and egress grants remain unavailable.
No source archive, dependency installation, project build, or upstream test ran.

Hold-out inspection read only commit metadata and the root license.
It did not read source, manifests, tests, issue descriptions, or task contents.
No sealed task bundle was created, opened, or used for fixture design.
Public repository identities are candidate metadata; they are not sealed task definitions.

The owner must appoint an independent custodian and two annotation engineers.
The custodian must attest that no target belongs to the predecessor estate or was previously configured for Crewshal.
Use separate development and hold-out stores, access lists, source copies, and annotation records.
Do not index sealed task contents in the development knowledge graph.
Publish only their opaque IDs and content commitments before grading.

The proposed corpus contains libraries and two related Pallets projects.
This selection can bias setup results and does not yet establish the required challenge features.
The feature map therefore records pending evidence for workspaces, generated code, multiple test targets, misleading documentation, known failures, and absent harnesses.
Replace unsuitable candidates prospectively. Preserve the replacement reason and prior selection record.
Public source may occur in model training data. Task secrecy cannot establish source novelty.

## Proposed protocol

The original numerical thresholds remain proposals.
The owner must still define a material per-stack quality margin and the required B2 advantage.
The protocol makes the full role factor explicit: 192 development runs and 576 sealed runs.
These counts double the original 96/288 planning counts by testing both assignments in each unit.
The eight development repositories remain separate from the four hold-outs.
Select one development repository per stack for the stated four-repository calibration shape before runs.
The other four remain development inputs for protocol preparation.
A smaller campaign requires a prospective shape and an explicit statement of reduced power.
Optional review ablations have no approved run count or spending allowance.

The ordering contract uses SHA-256 sorting with a recorded seed and canonical key.
Freeze its complete schedule before the first run.
Use fresh source copies and isolated writable caches for every condition.
Record provider cache counters and unknown provider cache behavior.
Measure cold setup separately from repeated tasks. Report observed amortization over 1, 5, and 20 tasks.

Use opaque result IDs for independent human grading.
Keep the condition mapping with the custodian until grades and adjudication are fixed.
Record unavoidable identity clues and failed blinding.
The review and grading bundles must identify exact source and check evidence without implementation reasoning.

Create a planned record for every unit before execution.
Retain unsupported, blocked, failed, interrupted, cancelled, unknown, waived, and successful outcomes.
Report supported-case accuracy and total coverage separately.
Report median, p90, paired differences, per-stack results, and uncertainty intervals.
The proposed small sample supports exploratory comparison only.
Do not claim statistical non-inferiority from this package.

Deduplicate usage by attempt and event identity. Preserve counter resets and contradictions as unknown.
Keep measured billing, price-based estimates, subscription quota, and missing usage in separate fields.
Count review, failed attempts, remediation, and approved ablations in their actual condition totals.
Do not price subscription quota as actual billed dollars.
Refuse a required hard financial cap without provider enforcement evidence.
The spending, quota, retention, and egress fields remain unapproved.

## Preparation acceptance and freeze boundary

Run the offline package and existing coordinator suites from a fresh checkout.
The tests must create their own source copies, state, and synthetic inputs.
They require no public-network retrieval, historical VM object, provider inference, or paid service.
The package tests check content hashes, four-stack slots, role assignments, unknown accounting, and closed authority fields.
Existing coordinator tests check provider independence, candidate binding, forged evidence, conflict, and remediation.

Preparation passes only when those checks and the required publication checks pass.
Phase 3A freeze additionally requires every item in `decisions.json.required_freeze_evidence`.
These requirements include independent annotations, actual task commitments, owner decisions, exact identities, and baseline conformance.
Those gates remain unsatisfied. Phase 3A is incomplete, and Phase 3B remains closed.
