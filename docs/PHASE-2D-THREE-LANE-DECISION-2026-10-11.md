# Phase 2D fixed three-lane schedule — owner decision

Date: 2026-10-11.
Status: **The owner accepted the source architecture amendment. Implementation remains in progress.**

The owner answered on 2026-10-11: "Approve the three-lane source structure".
This answer accepts the fixed three-lane source structure and the 448 MiB shared root allowance.
It does not approve the separate operational batch.

This proposal permits the two required qualification fixtures and one later live implementation attempt under one original retained owner.
It requests a source architecture decision only.
It does not request operational approval.
No compiler, Linux mutation, authentication, model request, or subscription exposure follows from this decision.

## Exact source obstruction

The owner requires all twenty original Linux cases twice on one exact changed profile.
The owner also requires one actual frozen-candidate and credential-free-validator live acceptance.

The current source has a singular installation lifetime:

- `reserve_storage_installation()` consumes the original observer's installation attempt.
- `OwnedStorageReservation.claim()` accepts one namespace lifetime.
- `create_namespace_setup()` consumes the observer's `_setup_started` field.
- `stage_namespace_parent()` supplies one native handoff for that parent.
- `prepare_validator_attempt()` accepts one original validator attempt.
- `prepare_stopped_native_bridge()` accepts one original installation bridge.

These functions correctly refuse ordinary replay.
Resetting their one-shot fields would evade that refusal.
Creating three independent reservations would charge `25769803776` logical and allocated bytes each.
That exceeds each original `8589934592`-byte ceiling.
Accepted retained ownership supplies no refund or resource reuse.

[ADR 0002](decisions/0002-minimal-architecture.md) reserves material architecture changes for owner review.
[ADR 0004](decisions/0004-retained-terminal-storage.md) requires one retained owner, unchanged limits, and no resource reuse.
[ADR 0006](decisions/0006-upfront-installation-charge.md) permits one original fully charged bootstrap reservation.
This proposal changes the singular lifetime contract while preserving those controls.
It does not reopen their accepted decisions.

## Proposed decision

Permit exactly three predeclared, disjoint, one-use lanes within the original installation:

1. `qualification-1` performs the first complete twenty-case fixture.
2. `qualification-2` performs the second complete fixture on the same frozen profile.
3. `live` performs one official subscription implementation turn and its separate credential-free validator.

Keep one original observer, synchronous journal, irreversible full charge, aggregate, physical domain, and batch timer.
Allocate all lane role groups and backing volumes before installation seals.
Give each lane actual distinct role, namespace, backing, mount, bridge, and process handles.
Use the existing native/tool, validator, observer, broker, CPU, memory, task, and zero-swap limits.
Activate lanes globally in sequence.
Never add a second simultaneous worker allowance.
The original aggregate limits apply to all lanes together, including their diagnostic processes.

Each lane has one original five-second native origin and one original five-second validator origin.
Each original recovery grace remains one second.
No origin or grace restarts after refusal.
The original batch origin precedes preparation.
All lanes share its 600-second end, 570-second cutoff, and fixed final 30-second reserve.
Startup remains at most 120 seconds; each storage job remains at most 30 seconds.

Do not reset, retry, replace, reconstruct, or reuse a lane.
Retain each terminal lane's handles and unknown results.
Require independent terminal process observations before activating the next lane.
Unknown operational children prevent further activation.
Stop the schedule on any failed, unavailable, incomplete, malformed, or stale mandatory result.
Permit the live lane only after both complete qualification fixtures pass independently.
Its one implementation turn remains the only real task attempt.

All twenty original cases remain mandatory twice.
Every actually enabled native file tool remains mandatory in both fixtures.
The changed profile must bind the full schedule and every effective native/tool control.
A different provider, authentication, loaded policy, or tool configuration cannot inherit qualification.
The operational proposal must demonstrate the exact synthetic/live transport binding.
This decision supplies no evidence for that binding.

## Storage fit and required reduced root bound

The existing conservative storage calculation is `7147094016` bytes.
It leaves `1442840576` bytes below each original ceiling.
One unchanged five-volume backing set totals `167772160` bytes.
Its three charged representations total `503316480` bytes.

Adding two full sets and two frozen/output allowances gives `8220835840` bytes.
That leaves `369098752` bytes.
However, the existing `872415232`-byte root and three backing sets cannot fit the fixed physical domain.

Reduce only the shared copied-root allowance to `469762048` bytes, or 448 MiB.
The unchanged prepared allowance is `1073741824` bytes.
Nine `67108864`-byte authentication representations consume `603979776` bytes.
Their difference is the proposed root allowance.

The proposed root and three backing sets total `973078528` bytes.
The original `1073741824`-byte physical domain then leaves `100663296` bytes before metadata.
No physical-domain enlargement is proposed.

## Required source work after approval

1. Bind exactly three immutable lane IDs to the one original claim before installation.
2. Create three disjoint five-volume sets and exact role directories under the original physical domain.
3. Apply the reduced root bound to copy admission and independent readback.
4. Bind each lane's lifetime, namespace, bridge, native child, watchdog, and validator to its original slot.
5. Replace singular lifetime fields with three retained slots; never reset a slot.
6. Extend the one original batch timer's fixed FD inventory to every lane role.
7. Enforce globally sequential activation and original worker-before-later-role stop ordering.
8. Retain all original lane handles through constructor refusal, failure, and terminal observations.
9. Persist two independent complete qualification results in the original journal.
10. Deny the live lane until both results match the exact frozen changed profile.
11. Refuse extra, copied, replaced, reordered, stale, or repeated lane objects.
12. Verify complete source and installed-wheel behavior before preparing the separately approved operational batch.

The new source tests must create their own fixtures.
They must prove single-charge ordering, disjoint ownership, sequential activation, failure retention, and no lane reconstruction.
They must preserve the old singular-path refusal tests where that path remains supported.
Actual kernel, installed-root, tool, account, transport, and live acceptance remain separate gates.
