It does not create namespaces, reconstruct mounts/policies/credentials, launch the watchdog or expose an operational CLI. Its Popen/migration/ptrace source must not be invoked on the host using prospective hashes. The offline tests invoke it only with synthetic kernel and constructor effects.

The parent verifies its actual retained PID/start/parent/pidfd, root role, one thread, zero tracer, no-new-privileges, exact bounded setup capabilities, image/argv/environment/cwd, cgroup and mount/network/PID/user/time namespace identities. Supervisor population must contain exactly those two processes; wrapper/init placement is a separate trusted setup responsibility and cannot silently add a worker or supervisor PID. Original worker/aggregate controls and refusal counters remain unchanged.

The source placement candidate uses Linux's inheritance rule rather than migrating an already executing child. After observing the original armed watchdog, the single-threaded trusted parent writes only `0` to the pinned empty worker's `cgroup.procs`, verifies its own placement and original worker controls, and creates its direct `subprocess.Popen` child there. The independent watchdog covers the parent and a blocked Popen constructor during that interval. The child uses the existing exec-only setpriv mechanism to enter role 65534 and then the owned helper; no bwrap/systemd outer handle, Python preexec function or inherited privileged FD supplies native admission. The parent returns through a pinned self-migration to the supervisor and independently verifies that return before any worker refusal cleanup or helper/native handoff.

Linux's [cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html#processes) states that children are born in their parent's cgroup and moving the parent does not move its existing children. This supports the source candidate, not a qualified implementation on the target. The trusted parent temporarily shares the original **134217728-byte, zero-swap, one-CPU, 32-task** worker ceiling; no additional worker allowance is introduced. The aggregate remains **805306368 bytes, zero swap, one CPU and 128 tasks**. Kernel charging, actual permitted migration, scheduling, wrapper/init topology and the five-second feasibility still require exact Linux qualification.

Initial traced attachment opens the independently checked standard procfs and boot identity, obtains and verifies the retained pidfd, and requires the parent's own exact traced helper identity. Its dedicated factory allows only this initial `t` checkpoint. **RetainedProc.attach and native admission are unchanged** and still require `T`/zero tracer. The bridge shares the retained initial PID/start/parent/boot/pidfd and namespace identities with the previous owned exec-event/SIGSTOP-delivery/detach handoff. ## Independent watchdog readback and refusal lifetime

The watchdog remains a separately created actual Popen child of this trusted parent, with exact owned helper bytes, empty environment, root UID/GID, empty groups/capabilities, one thread, zero tracer and the same namespace/clock identities. The packaged C source now explicitly refuses a timer descriptor other than FD 6 before readiness. No C compilation or executable installation occurred.

The parent independently verifies the watchdog's armed descriptor inventory: namespace null-device stdio, FD 3 matching the pinned owned worker cgroup.kill device/inode and write/nonblocking mode, FD 4 matching the parent's retained lifeline pipe and read direction, FD 6 referring to timerfd, and no remaining readiness FD or other descriptor. It observes CLOCK_MONOTONIC, zero expiration count, absolute settime flags, zero interval and required timer FD flags. Linux [proc fdinfo documentation](https://man7.org/linux/man-pages/man5/proc_pid_fdinfo.5.html) specifies that it_value is relative even for an absolute timer. The code therefore brackets that read with monotonic clocks and requires the reconstructed absolute expiry to contain the **original acknowledged expiry**, without tolerance that permits an extension. Matching time namespace identity prevents comparing unrelated clock offsets.

This effective readback and cancellation check precede self-migration and Popen. Watchdog checks continue through the existing handoff and final admission. The retained watchdog is consumed once; this source supplies no retry, reset, disarm or reuse while it survives. The original **five-second origin includes bootstrap/admission** and the original **one-second refusal grace** persists.

On a refusal after the parent is observed outside the worker, the bridge retains the parent, watchdog, child/proc when available, lifeline/kill handles and all three owned cgroups. It stops only the pinned worker and observes population/reaping within one grace. A handoff refusal does not start a second recovery grace. Handoff interruption similarly preserves the already attempted recovery as unknown when its result was not returned. If return migration cannot be observed, the bridge attempts no worker kill that could kill its own cleanup parent; it retains an explicitly unknown recovery and the original independent watchdog remains armed. These retained error objects are not cleanup completion. Terminal watchdog/resource lifetime observation, external recovery if the parent dies, owned unmount/key/backing cleanup and a safe eventual reuse decision remain missing source/qualification work.
