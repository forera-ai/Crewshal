## Concrete pinned readback source

[LinuxPhysicalOwner](../src/crewshal/linux_storage.py) implements the existing trusted `PhysicalOwner` interface. It duplicates namespace, private backing-directory and loop FDs, pins their actual inode/device identities and opens the boot-bound standard host proc mount through the existing retained route. It binds the exact session configuration and requires backing-directory kernel path readback inside the exact session root, root ownership and exclusion of untrusted directory mutation. A constructor refusal retains acquired handles and its claimed ring in `StorageOwnerRefusal`; it does not clean an unknown partial lifetime.

Mountinfo parsing covers all rows, decoded kernel escapes, mount IDs, parents, devices, filesystems and exact targets. Initial owned IDs come from this readback. Changed IDs, moved owned mounts, stacked targets and filesystem substitution are refused. An owned ext4 mount must refer to a currently observed owned loop. Loop readback uses the 232-byte Linux `loop_info64` layout, decodes the kernel device encoding, and compares the retained block node, major 7, loop number, exact backing device/inode, zero offset, bounded nonzero size and allowed flags. Only `ENXIO` means an unbound loop; denied or malformed reads remain unknown. Paths and loop file-name text do not establish backing ownership.

`AnonymousKeyring.create()` is future trusted setup source, never a discovery operation. It reads the previous session ID without creating it, joins a new anonymous ring with a NULL name and independently describes that exact positive serial as a root-owned `_ses` keyring. It does not mutate, clear, link or revoke an inherited ring. Failed new-ring readback retains its observed serial without asserting ownership. The retained object is claimed once; later serial/provenance mutation is refused. This creation path has not run and still needs qualified setup containment and installation. Kernel `EKEYREVOKED` alone means observed revocation; `ENOKEY`, expiry or access denial cannot substitute. Anonymous creation and description are documented by [Linux man-pages](https://man7.org/linux/man-pages/man2/KEYCTL_JOIN_SESSION_KEYRING.2const.html) and [KEYCTL_DESCRIBE](https://man7.org/linux/man-pages/man2/KEYCTL_DESCRIBE.2const.html); errno distinctions are specified in [keyctl](https://man7.org/linux/man-pages/man2/keyctl.2.html).

Backing leaves use a pinned directory FD, exact device/inode, regular-file type and a single link. The concrete owner accepts the exact private backing FD transfer from `OwnedPhysicalResources`, so extra FD exclusions refer to actual retained copies, not caller-reported absence. Leaves are checked immediately before relative unlink. Missing paths never mean released allocation.

## Bounded operation source and retained failures

Fork inherits these controls; no migration, exec, extra sibling role or new resource allowance is added. The child waits on a private admission pipe until the parent retains its pidfd, requests parent-death SIGKILL and checks its actual parent before effects. It closes unrelated inherited FDs before namespace readback/effects. This is source only: there is no entry point or installed observer program here.
