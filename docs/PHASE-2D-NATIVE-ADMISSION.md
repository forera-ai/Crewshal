## Observable behavior and trust

[Admission source](../src/crewshal/admission.py) adds read-only admission for an already created, stopped native child retained by trusted setup. It creates no process, envelope, cgroup, mount, role policy, network rule, credential channel or owner approval. It sends no signal and does not resume the child. A prospective launcher must obtain its own exact source/configuration qualification and separately recorded startup/execution/spend gate before creating that child.

`RetainedProc.attach` is Linux-only. It checks the standard proc mount, boot identity and actual pidfd PID, retains a proc directory descriptor and a pidfd, and verifies a live stopped PID/start-ticks/parent identity. Admission requires a single thread, no tracer, native real/effective/saved/filesystem UID/GID 65534, no additional groups, empty capability sets and no-new-privileges. The proc status/stat reads bracket configuration/FD readback so a resumed, exited or changed child cannot produce a receipt. Directory and pidfd handles are closed by the owning caller; this module does not infer cleanup authority from a numeric PID.

The source reads bounded native argv and initial environment, compares the exact pinned dispatch settings, checks cwd and cgroup membership, and hashes the actual executable through the fixed proc magic link. Namespace device/inode observations must match identities independently retained by trusted setup. Executable reads ignore atime changes caused by the read itself, while checking bytes, identity, size, mode, owner, mtime and ctime. Reads retain at most 65,536 bytes; executable hashing streams at most 128 MiB without retaining the binary. Malformed, duplicate, oversized, missing and unavailable interfaces refuse.

The stopped bootstrap checkpoint must have only FDs 0/1/2, each matching the coordinator's separate task/stdout/stderr pipes and expected direction. FD enumeration stops after a fourth entry. No token is read or written; unknown broker/transport FDs refuse. Extra descriptors opened by a native runtime before the checkpoint would require a concrete compatibility decision and fresh qualification, never silent acceptance.

Worker and aggregate cgroup identities are independently retained. Source verifies immediate ancestry using the worker descriptor's actual parent device/inode rather than pathname comparison alone. Worker readback retains the original 128 MiB/zero-swap/one-CPU/32-task controls and exactly the stopped native PID. Aggregate readback requires 768 MiB/zero-swap/one-CPU/128-task controls, an empty direct-process list and zero resource-refusal history. Admission elapsed time counts against the original five seconds, including time before admission. This is cooperative refusal; independent hard deadline enforcement remains a launcher obligation.

`AdmittedNative.capture` joins retained child, pipes, worker cgroup and original launch clocks to the existing [bounded supervisor capture](PHASE-2D-SUPERVISOR-SOURCE.md). It rechecks dispatch/source, aggregate controls, child PID and retained capture-pipe identities before collection. It does not release the stopped child or provide a new CLI command. Its receipt keeps execution, spend and profile qualification false. Receipt persistence and linkage to `collect_supervised_codex` remain future integration work; no admission receipt currently establishes a durable verdict predicate.

[Dispatch](../src/crewshal/dispatch.py) now binds thirteen current package files, including admission source. Earlier prospective configuration identities become stale. Internal descriptor constructors are trusted coordinator seams used for explicitly synthetic offline fixtures; a Python object or parsed receipt does not prove a kernel capability. Trusted directories, retained child ownership and setup provenance remain assumptions, with no malicious same-user/administrator defense claim.

## Evidence and practical limits

[Twenty-eight new independent methods](../tests/acceptance/test_phase_2d_admission.py) create actual pipes, regular files, symlinks and directory descriptors. Proc, namespace, cgroup and pidfd effects are synthetic. The child is an explicit `Popen` subclass whose process constructor is never called. macOS gives pipe ends different inode values; synthetic proc links model Linux's pipe identity using the retained parent descriptor. No Linux attachment, child startup, signal, kernel enforcement, provider request or credential access occurs.

Cases cover valid retained identity with false authority; PID/start/parent/stopped changes; pidfd exit readiness; changed privilege/group/thread/tracer status; missing/duplicate status; argv and initial-environment changes; cgroup migration and cwd changes; namespace and executable substitution; extra/inverted/aliased/wrong pipes; resource-refusal history; relaxed aggregate controls; actual directory ancestry; descriptor pinning through pathname replacement; oversized/FIFO/symlink readback; stale source/configuration; expired clocks and deadline expiry during admission; state mutation during readback; capture integration; swapped capture pipes; changed aggregate before capture; missing/reaped handles; schema/topology/platform refusal.

Matching namespace identities does not prove that a namespace is private or correctly configured.
