## Smallest proposed amendment

1. Add a distinct installation-charge record to the original synchronous journal. Keep the existing installed-domain contract and its installed-to-retained path unchanged. The new record always contains the original observer/configuration/origin and the full original charges; it has no available/free state. Its initial state is `preparing`, with installation proof unknown.
2. Commit the full charge before namespace, root, backing, loop, key or mount creation. Mint one strongly retained, nonserializable claim in the original store and bind it once to the original reservation. A new/missing/replaced journal, restart, failed creation or record reconstruction cannot mint a replacement for this attempt.
3. Use the same original observer, aggregate, roles and timer. The original 600-second origin starts before this preparation; cutoff stays 570 seconds, startup stays 120 seconds, each storage job stays at most 30 seconds, and the final 30-second reserve is untouched. No second observer, installation allowance or renewed origin is permitted.
4. Installation preparation may use that original charged reservation. Native/watchdog/validator admission remains denied until the same live installer independently reads actual retained physical-domain/root/journal identities and every applicable growth/control bound. Record readiness only from that live readback; neither a serialized result nor a digest supplies it.
5. Record the result as fully retained with installation either observed or unknown. Both success and refusal consume the reservation; there is no refund, retry, new capacity, release or reuse transition. All partial handles, hidden references and original charges remain retained. An unknown operational child prevents idle-retention acceptance.

The full charges stay memory **805306368 bytes**, **128 tasks**, logical and allocated storage **8589934592 bytes each**. Existing per-role limits, one CPU/zero swap, candidate 16777216 bytes, scratch 33554432 bytes, stopped-native admission, five-second origin, one-second recovery grace and terminal native/watchdog/parent/wrapper ordering remain unchanged. Existing accepted private anonymous keyring, namespace, ext4/eCryptfs and owned loops remain the mechanisms. No ambient keyring operations, lazy/forced unmount, host block-device cleanup, metered API, custom model loop or Phase 2E.

This changes the prerequisite for installation creation from preinstalled capacity to an upfront original-owner charge followed by independently observed installation.
