## Exact remaining incompatibility

Closing owned loop FDs is a necessary step. The existing per-job fork retains a parent duplicate, so its child cannot perform the final close. Closing that parent duplicate after reaping the child moves potentially blocking release into the observer. A bounded sole storage holder must own the final reference from creation; a later transfer cannot be assumed to complete without a race or a retained duplicate. This handoff is missing. The presently accepted readbacks still provide no verified per-object witness that the retained backing file's last kernel/path/inode reference has finished destruction, together with exclusion of new attachments through the final transition. Upstream loop unbound/status publication precedes backing `fput`; the earlier [commit-bound source record](PHASE-2D-STORAGE-CLOSURE-BLOCKER-2026-10-09.md) preserves this evidence. Target kernel identity is now observed, but upstream bytes are still not vendor-kernel qualification.

A write lease alone does not fill the gap. In the same upstream commit, [`lease_open_conflict`](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/fs/locks.c) compares inode read/write open counts after subtracting the requesting file's count. That is not an enumeration of references to that open file or of every inode/path reference. In [`__fput`](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/fs/file_table.c), file-access accounting is dropped before dentry/mount references and final file destruction. No lease, exclusive block-device claim or advisory lock was executed or adopted as a release oracle. These source observations reject those shortcuts; they are not an exhaustive impossibility result about Linux or a measured target-kernel experiment.

The constructor still accepts pre-existing namespace/directory/loop/backing FDs. It cannot reconstruct enforced reference ownership from creation. Taskless namespace pins, deleted-open/mapped references, in-flight socket references, asynchronous/deferred work, extra or delayed loop attachments and concurrent mutation remain unresolved. Positive findings block cleanup; empty observations remain unknown. The ordering approval does not authorize backing unlink, observer/aggregate release, reuse or a second attempt.
