## Implemented and verified

There is no installation initializer, refund, reset, release or restart-reconstruction API. A missing domain or fresh database means unknown capacity. Claiming requires the exact complete installation history and commits the full synchronous transaction before returning a live token. Concurrent claimants can commit only one claim. Journal replacement, missing events, changed durability controls or reset history deny continued admission. The original store also retains the exact minted token identity; copying matching record/path/hash fields into another Python object cannot reconstruct it.

An `OwnedStorageReservation` requires that original live claim before any creation. It binds the exact original observer, configuration and batch origin and retains full charges even when verification fails. This is denial accounting, not proof that a physical pool is installed or available. Fresh offline fixtures explicitly create synthetic installation records through the private data seam; they are not an operational installer.

The new [partial producer](../src/crewshal/linux_production.py) pins its original reservation and job before acquisition. A fixed acknowledged SCM_RIGHTS sequence transfers actual namespace, loop-control, backing and loop descriptors. Received descriptors are retained before parsing or metadata verification. The child waits for parent custody before namespace propagation changes, backing truncation or loop attachment. Backings have fixed logical sizes 33554432 and 16777216 bytes. A busy or rundown loop refuses atomically at SET_FD; there is no search retry, detach or host cleanup. GET_FREE and ENXIO are never release evidence. Potentially blocking loop status reads run in a separate bounded job, not the retaining observer.

Creation transport pins the actual child pidfd and proc directory before admitting effects. Boot, parent, start ticks, proc identity, liveness, UID, threads, no-new-privileges and observer cgroup are independently read. Only that producer's retained child may accompany the observer during reservation readback; ordinary readback still requires the observer alone and any additional task refuses. Unknown jobs and partial handles remain charged and retained. No serialized PID list, command exit, transport message or completion flag supplies operational readiness or release.

Subscription preparation now reaches the envelope and namespace plan intact. Native, parent, watchdog, admission and C helper use the exact `/candidate/owned` subscription cwd. This corrects source inconsistencies; it does not demonstrate actual helper, tool or credential isolation. The C helper remains uncompiled.
